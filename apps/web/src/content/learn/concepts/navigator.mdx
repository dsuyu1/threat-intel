# Navigator

Navigator is the platform’s CTEM-style workflow: it connects **threat actors** to **your environment** and turns that into:

- Prioritized **scenarios**
- Concrete **actions**
- Generated **detections** (Sigma/KQL/SPL)

## What a scenario is

A **scenario** is a unit of modeled risk. It combines:

- An **actor** (who)
- A **target** (your stack / assets / detections) (what you run)
- A **technique**, CVE, or IOC signal (how)

The output is a score you can sort and work down.

## Scoring (FAIR-lite, in plain terms)

Navigator uses a “FAIR-lite” framing for stakeholder-friendly estimates:

- **SLE (single loss expectancy)**: impact if it happens once (loss magnitude)
- **ARO (annual rate of occurrence)**: how often you expect it per year (loss event frequency)
- **ALE (annualized loss expectancy)**: SLE × ARO

In the product, you’ll see these represented as:

- **Loss event frequency (per year)** (ARO/LEF)
- **Loss magnitude low/high** (SLE range)
- A derived annualized range (ALE)

## What a detection is

A **detection** is a rule generated for a technique:

- **Sigma** (portable)
- **KQL** (Microsoft/Sentinel-style)
- **SPL** (Splunk-style)

Detections are tied back to scenarios so you can measure “coverage”.

## The scenario → action → detection pipeline

1. **Scenario**: the modeled risk unit
2. **Action**: what you should do next (instrument, investigate, deploy a control)
3. **Detection**: an executable rule for the technique (generated and tracked over time)

## What “coverage” means

Coverage is a shorthand for “how much of this scenario’s technique surface area is detectable”.
At a high level:

- 0% coverage: no detections exist for relevant techniques
- Higher coverage: more techniques have at least one detection and/or completed actions

<Callout type="tip">
If you want to improve coverage quickly, start by generating detections for the top scenarios and deploying them into your SIEM.
</Callout>

## MITRE matrix map (buckets / heat)

The **MITRE matrix map** (also called the “Defend heatmap”) shows ATT&CK techniques grouped under tactics, with each
technique colored by a **bucket** from **0 → 5**.

### What “heat” means

**Heat** is the tile’s **color intensity**. Hotter colors mean a higher bucket.

### What the buckets mean

- **Bucket 0**: the selected metric is **0** for that technique (no activity / no evidence for the current dataset).
- **Buckets 1–5**: a **relative** scale. We take the metric for all techniques, apply a log transform
  (`log(1 + value)`), then split non-zero values into **5 quantiles (quintiles)**:
  - 1 = lowest 20% of non-zero techniques
  - 5 = highest 20% of non-zero techniques

Because buckets are quantile-based, **Bucket 5 means “hot relative to the rest of the current dataset”**, not an
absolute threshold.

### What metric is used

By default, the heatmap uses **findings mentions** for each technique in the selected time window. If there are no
MITRE-tagged findings yet, the UI may fall back to other signals (like **actor prevalence**) so the matrix still has a
useful “shape” until findings start including technique IDs.
